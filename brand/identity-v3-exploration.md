# Arai Hû identity v3 · exploration

## Art direction

The family uses a constructive module system rather than a collection of
literal illustrations. Its source is Brazilian geometric abstraction: limited
primitives, active negative space, repetition, and variation. Athos Bulcão's
combinatorial use of straight segments, semicircles, and diagonals supplies the
construction vocabulary; Hélio Oiticica's *Metaesquemas* supplies the idea of
small geometric forms activating the surrounding field.

No artwork, tile, or protected mark is traced. The sources define constraints:

- 8 px base grid inside a `128 × 128` field;
- straight, diagonal, circular, and semicircular moves;
- midnight structure, cobalt secondary plane, one lime state change;
- open silhouette rather than a shared app container;
- no texture, gradient, shadow, fine line, or ornamental symbol.

## Two exploration lanes

`A` favors a recognizable object or operational artifact. `B` favors a more
abstract technical diagram. The review sheet tests both at 128, 32, and 16 px;
neither lane is production.

| Product | Actual product anchor | Lane A | Lane B |
| --- | --- | --- | --- |
| Arai Hû | Name means a black or dark cloud | Constructive storm front | Layered weather field |
| Goshtoso | Composable server-rendered UI components | Interlocking component stack | Two-way rendered interface flow |
| Manja | OpenAPI renderer and publisher | Spec sheet with path tree | API boundary with path hierarchy |
| Pajé | `resolve → execute → approval → publish → finalize` | Durable rectilinear loop | Retry loop with five checkpoints |
| Xisnove | External probes become health and incidents | Protected railway block | Monitored network crossing |

## Selection rule

Do not choose by decoration. Select one lane per product only when its first
reading remains useful at 32 px, the product anchor can be explained without a
new metaphor, and the five selected marks still look authored by one system.
