# Goshtoso and App Shell Campaign Integration Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Prove Goshtoso remains compatible with the released Assets catalogs and give both Goshtoso App Shells a generic, explicit integration API for deferred presentation channels.

**Architecture:** Goshtoso keeps its released brand-neutral icon component, generated Heroicons names, default sprite, and showcase. It consumes the new catalog only as a generator compatibility fixture. Goshtoso App Shells adds an opt-in presentation-channel configuration, fixed-size managed brand assets, first-paint source markers, and a hidden toggle hook; the Assets runtime continues to own campaign policy.

**Tech Stack:** Go 1.26.5, templ v0.3.1020, Goshtoso v0.1.x, vanilla embedded shell JavaScript, Node/browser E2E already in Goshtoso.

## Global Constraints

- Base Goshtoso work on refreshed `origin/main` at or after `7a874e4`, which already contains the released icon component and showcase.
- Do not add Arai Hû campaign IDs, dates, calendars, or asset canonical names to Goshtoso public packages.
- Goshtoso App Shells remains generic. It renders declared hooks and source state; it does not fetch or resolve channels itself.
- Existing shell configuration remains source-compatible when presentation-channel fields are unset.
- Existing storage keys remain unchanged: component docs uses `theme`/`darkMode`; console shell uses `goshtoso-theme`/`goshtoso-dark`.
- The runtime trusts `data-theme-source`; shell code must not require it to inspect application storage.
- Use Go 1.26.5. Regenerate templ/JS/CSS through repository commands.
