# Arai Hû Assets v0.1.0 Control-Plane Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Coordinate isolated, reviewable delivery of assets `v0.1.0`, Goshtoso icon support, the engineering proof, and the public Arai Hû brand site.

**Architecture:** A root control plane owns one persistent ledger and integrates bounded branches from three repositories. Shared catalog and artifact contracts land in `assets` first; dependent Goshtoso, proof-site, and `araihu.com` work starts only from recorded immutable commits.

**Tech Stack:** Git worktrees, Markdown ledger, Go 1.26.5 across all in-scope modules, templ, Tailwind CSS v4, static HTML verification, Cloudflare Workers static assets.

## Global Constraints

- The first assets release is `v0.1.0`; `v1.0.0` remains reserved for a complete stable icon contract.
- `catalog.json` and release artifacts are the interoperability contract; `araihu-assets` performs no client code generation in `v0.1.0`.
- `icons/brand` contains Arai Hû-controlled identity marks; `icons/ui` contains permissively licensed UI icons.
- Heroicons is pinned to `v2.2.0`, selected through an explicit allowlist, and redistributed with its MIT notice.
- Public asset paths never contain `v11`; catalog entries retain `identityRevision: 11`.
- Git history is the archive; the release tree contains no historical numbered concept or proof directories.
- Every implementation branch uses an isolated worktree; dirty primary checkouts are preserved and never cleaned.
- The root control plane is the only writer to the ledger and integration branches.
- `assets`, `goshtoso`, and `ahairu` declare and test with `go1.26.5`, the latest stable Go release on 2026-07-29.
- No tag, push, merge to protected branches, or production deployment occurs without a final user checkpoint.
