# Arai Hû Asset Proof Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the hand-wired V11 review with a catalog-driven engineering proof that exposes brand and icon defects across realistic web and mobile contexts.

**Architecture:** A Go proof builder consumes the frozen release-candidate catalog and scenario data, verifies every referenced asset, and emits a self-contained static site under `dist/proof`. Small local CSS and JavaScript files provide responsive comparison rails and shareable controls; no CDN or runtime framework is required.

**Tech Stack:** Go 1.26.5, `html/template`, static HTML/CSS/JavaScript, local HTTP server, browser screenshots, Impeccable visual review.

## Global Constraints

- Proof consumes the recorded assets release-candidate commit and schema v1; it does not invent paths or variants.
- Evaluation covers every product, icon/logo artwork, declared appearance/surface/framing, and UI sprite seed.
- Exact icon evidence includes 16, 20, 24, 32, 48, 64, 128, and literal 512 pixels.
- Circle/squircle shapes are simulations around mask-safe assets, not new canonical files.
- Every meaningful specimen has a programmatic product/artwork/variant/size label; adjacent visible labels permit decorative images.
- Geometry metrics use semantic tables; controls are keyboard-operable and visibly focused.
- Light, dark, transparent, plate, monochrome, and designed tinted cases remain distinguishable.
- Generated proof files are deterministic and enter the release archive.
